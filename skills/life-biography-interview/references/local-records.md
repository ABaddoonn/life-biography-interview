# 本地访谈档案与新会话接续

这是公开方法说明，不含任何真实访谈。以下模板只有字段，不代表已经保存用户内容。

## 先说明、获准，再创建

1. 已有用户明确指定的传记目录时采用该位置；没有时建议当前电脑用户主目录下的独立“人生传记”目录，使用不包含敏感身份的名称区分不同传记。依据实际系统确定路径，不猜用户名、不默认放临时目录或当前项目。
2. 展示完整路径，用简单话说明将保存相关访谈原文、反馈与问题、进度、纠正和待核实事项；它们用于用户本人阅读和新会话接续，不会自动公开。只问一个许可问题。用户明确同意保存并指定位置，或接受建议后，视为授权在此范围内后续保存，不每条回答重复询问。
3. 同意后直接用可用文件工具创建目录与两份文件：`访谈记录.md`、`访谈进度.md`。有系统权限要求就走批准界面；用户拒绝不绕过。目录或文件已存在时先读，不能覆盖旧传记或混入另一人的记录。
4. 确认目录与文件创建成功，告诉用户保存位置，再开始正式访谈。没有新材料时只准备结构，不声称旧聊天已入档。导入已有访谈要用户明确授权且能访问原文，不能把当前总结当完整聊天记录。
5. 无写入工具时说明能力限制，再引导用户在同意的位置建立文件夹并保存接续卡；不让用户复制复杂命令。用户拒绝独立存档仍可访谈，说明新会话需贴回接续卡。不承诺关闭平台自身的聊天保存功能。

若选择的目录在 Git 仓库、云同步盘或共享目录里，先提醒同步或发布风险，优先改为用户认可的独立私人位置。确需沿用时讲明风险并获得许可；未获授权不改 `.gitignore`，不提交、推送或上传档案。

## 两份文件各自做什么

### 访谈记录.md：保留原始依据

按实际对话顺序记录与访谈有关的采访问题、受访者回答、采访者对外反馈与受访者纠正。标明谁说的话，受访者原话不静默润色，转写疑点另注。自己的解释与受访者陈述分开，不存内部推理、工具秘密或无关聊天。

示例结构：

```markdown
# 访谈记录

## 本轮

### 问答条目
- 采访问题：
- 受访者原话：
- 对外反馈：
- 后续纠正或转写疑点：
```

字段只在有内容时填写，不复制空白问答来表示已有进度。已经记录的消息不重复追加；新会话也不重写成不同原话。

### 访谈进度.md：告诉新会话从哪里继续

维护一份当前状态，不另建重复状态库：

```markdown
# 访谈进度

- 传记对象与阅读范围：
- 获准保存的路径与范围：
- 本轮状态、已用问题数与结束边界：
- 当前阶段：
- 已覆盖的阶段及状态（可写／有关键疑点／材料有限）：
- 当前时间线与人物关系：
- 已问、已答的主要内容与原始记录位置：
- 最新明确纠正：
- 待核实的关键事项：
- 暂定理解（可选）：适用范围、原始材料位置、已有反例或不同解释、尚未确定处
- 记不清、不愿谈、不要再问的内容：
- 不记录、不入稿、不公开的边界：
- 可写章节：
- 最后已处理的问答位置：
- 已发出但未回答的问题：
- 接下来应做什么：
```

暂定理解只有确需保留时才写，不能冒充受访者原话或新的事实。旧档缺少这个可选字段仍可直接接续，不要求迁移、不重做采访，也不新增第三份文件；旧总结中的解释须核回原始记录后再使用。

没有可靠计时记录就写未计时，不补造时间。阶段只有概况也可记录为可写；记不清与不愿谈分别记录。进度的每项重要事实指向原始问答，保留修正，不把推断升级为事实。

## 每次回答之后保存

- 收到回答后先检查是否有禁止记录或撤回要求，再把获准的原文和相关问答保存到记录文件，随后更新进度，最后才推进采访。新发出的下一问记录为待答；还没有发出的计划只写在“接下来应做什么”，不能当成已问。
- 用宿主现有的文件写入或编辑工具，不为了存档新增后台任务、自动同步器或全局记忆。修改已有文件前读取当前内容，避免覆盖其他会话的新记录；发现并发修改先停止相冲突的写入。
- 根据文件工具的确认结果核实保存成功；工具未确认成功时，读取精确目标确认，不能仅凭执行命令就说已存。收到问题数和隐私变化时一并更新，不把保存操作当额外访谈问题。
- 用户不想记录的内容不落盘；仅不公开的内容可以按已获准范围保留在私人档案，并在进度注明。撤回已保存内容时按要求清除相应原文及派生摘要，只保留不含细节的限制提示，避免下一会话再次追问；不能保证已存在的平台历史或其他备份也已清除。
- 保存失败时立即说明从哪条开始未保存，保留最后成功状态，给可复制的接续卡或获准后更换可写目录。不继续声称自动接续可靠，不丢掉原始材料来制造“保存成功”。

## 新会话从哪里继续

1. 用户给出路径就读该目录；未给路径时，仅检查已约定的默认私人位置或当前可访问的传记目录，不扫描整台电脑的私人文件。只有一个匹配且对象明确时直接使用；多个对象或未找到时只问文件夹在哪里或要续哪一份。
2. 先读 `访谈进度.md`，再读与当前阶段、待答问题、纠正及未定事实有关的 `访谈记录.md`。长文件分段读，不能只读开头就声称看完。查到原文与进度不一致时，优先核具体原文及最新纠正，不能忽略矛盾。暂定理解按其原始材料和适用范围读取，不能因上轮写进进度就认定已被事实证实。
3. 用一句话说明停点，例如“上次这一段已够整理，接下来聊下一阶段”，无需让用户复述已可读取的经历。未结束的同一轮继续原计数，已达上限则先交成果；开启新一轮需用户明确同意。
4. 待答问题确实已向用户发出且仍有必要时接着问；已有答案、被撤回或不想谈则取消，不重复。此前仅计划了一个问题而没发出时，按当前材料判断是否仍值得问。
5. 不依赖对话标题、Skill 安装位置或模型自称记得来接续。换电脑、云端环境或不同权限可能访问不到本地目录，要用户复制档案或提供可访问路径；从最后成功保存的位置继续，不承诺未保存的最后一条也能恢复。

## 检查边界

实际验证须覆盖：用户同意后才创建；拒绝仍可访谈；已有文件不覆盖；连续保存有原文与最新纠正；新会话不重复已答问题；保存失败不谎报成功。可用明确标注的虚构访谈与隔离目录测试。仅检查这份说明和文件链接，不证明任意 Codex、Hermes 或其他宿主已实际执行，也不证明所有已打开会话已经换版。
